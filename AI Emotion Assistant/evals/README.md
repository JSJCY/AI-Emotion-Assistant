# AI Emotion Assistant 评测集

## 目的

本目录保存 MVP 首版离线评测资产，用于在接入真实用户之前验证模型路由、结构化输出、情绪支持质量与安全边界。

- `dataset-v0.1.jsonl`：60 条人工编写的合成用例，不包含原型体验者或其他真实用户的原始对话。
- `scoring-rubric-v0.1.md`：自动门禁、人工评分维度和发布阈值。
- `manifest-v0.1.json`：版本、字段定义和预期分布，便于脚本校验。

## 单条用例字段

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定用例编号。 |
| `split` | `baseline` 为常规能力集，`red_team` 为对抗集。 |
| `category` | 场景类别。 |
| `risk_level` | 预期最高风险等级：`L0`—`L3`。 |
| `strategy` | 期望主策略：倾听、澄清、表达、行动或安全。 |
| `input` | 合成用户输入。 |
| `context` | 必要的短上下文；首版全部为空，后续另建多轮集。 |
| `expected_route` | 期望路由。 |
| `expected_artifact` | 是否应生成结构化产物。 |
| `must_include` | 语义检查点，不要求逐字匹配。 |
| `must_not` | 禁止出现的行为类别，不只是关键词黑名单。 |
| `tags` | 切片与回归标签。 |

## 使用顺序

1. 固定模型版本、系统提示词版本、温度和 JSON Schema 版本。
2. 每条用例在新会话中运行；最多允许一次由服务端触发的结构化格式重试。
3. 先跑自动门禁，再由两名评审独立盲评；分歧超过 1 分时复核。
4. 按评分标准计算总分，并单独检查所有 P0 失败与风险切片。
5. 模型、提示词、安全规则或输出 Schema 任一变化后，必须重跑全量集。

## 数据约束

- 不把真实用户原话直接复制进评测集；如需吸收真实失败案例，必须先获得授权并去标识化后重写为合成案例。
- 不在评测日志中保存 API Key、完整系统提示词或真实用户标识。
- 自伤、他伤案例只描述风险信号，不包含方法、剂量或操作细节。
