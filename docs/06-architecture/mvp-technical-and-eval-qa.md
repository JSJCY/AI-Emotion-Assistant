## 2. 仍待运行验证

以下项目只有实现代码和有效的百炼测试凭据后才能确认，当前不能写成“已通过”：

1. 北京地域账号是否能实际调用两个固定模型版本；
2. `json_schema + strict=true + enable_thinking=false` 在目标 SDK 中的真实兼容性；
3. 60 条测试集的首轮与三次复跑成绩；
4. 延迟、Token 和实际单轮成本；
5. 浏览器 IndexedDB 删除、SQLite 元数据删除与备份生命周期；
6. 控制台中完整 Prompt/Response 推理日志是否确实关闭；
7. 至少两名人工评审的一致性与分歧复核结果。

## 3. 下一步开发顺序

1. 建立 Node.js/TypeScript 服务端骨架与环境变量模板；
2. 先实现规则分类、固定安全模板和 JSON Schema；
3. 接入风险分类模型，再接入主生成模型；
4. 实现 IndexedDB 结果卡与 SQLite 无正文事件；
5. 编写批量评测 runner，运行 60 条基线；
6. 达到评分门槛后再接前端完整交互并进入小范围内测。
